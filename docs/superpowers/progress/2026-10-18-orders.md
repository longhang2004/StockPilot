# Orders workflow progress — 2026-10-18

## Scope delivered

The Orders workspace now uses URL state for search, status, page, selected order, create, and edit. Opening an order pushes `order=<uuid>` while preserving the other query parameters; reloading that URL fetches the object directly. The contextual object page includes order facts, line snapshots and SKU links into inventory trace, activity transitions, and an audit-history link. The list uses its accessible `Open <order number>` action for keyboard and pointer navigation.

Draft creation uses the existing `useCommandMutation` recovery path with a stable `Idempotency-Key` and exact submitted payload. Unknown outcomes retain the draft form intent across drawer close and reload, lock payload edits, and allow retry with the same key. The existing 23-hour client cutoff and server 24-hour key window remain unchanged. Draft editing uses `PATCH /orders/:id`; it fetches previously selected customer and product records by ID so paging the catalog does not erase line values. A 409 keeps the user-entered values and provides an explicit action to inspect the latest server order. Staff can edit Drafts and fulfill confirmed orders; Confirm and Cancel remain Manager/Owner actions. Status transition recovery remains available from both the list and object page.

## API and shared interfaces consumed

- `apps/web/features/orders/api.ts`: `fetchOrderDetail`, `fetchOrderCustomer`, `fetchOrderProduct`, `createDraftOrder(value, idempotencyKey)`, `updateDraftOrder(id, value)`, and `transitionOrder(id, target, idempotencyKey)`.
- `apps/web/features/shared/use-workspace-location.ts`: clones the current search parameters, preserves unknown parameters, and writes safe same-route push/replace navigation. The Orders debounce keeps a ref to the latest helper value so URL search updates do not restart their timer on every render.
- `apps/web/hooks/use-command-mutation.ts`: durable command storage is scoped by the active workspace; no command-storage semantics were changed.
- `apps/web/features/inventory/inventory-workspace.tsx`: invalidation uses the existing `['inventory-trace']` prefix and `['inventory-summary']` key after order status changes.

The API response types remain sourced from `@stockpilot/contracts` through `features/shared/types.ts`; the UI does not duplicate the wire contract.
