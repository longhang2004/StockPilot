# A1 Real-account sign-in and sign-out

## Implementation

- `/login` without `role` renders `components/auth/login-form.tsx`: focused email/password form against the existing CSRF-protected `POST /auth/login`. 401 shows "Email or password is incorrect…", 429 shows a throttle message, other failures show a retryable availability notice; the submit button is disabled while pending.
- After success, members route to `/app` and accounts with no membership go to `/create-workspace`; `router.refresh()` re-syncs the session. No password persistence and no invented password-reset link exists; the card links to signup and to the demo entry.
- `/login?role=manager|staff|owner` keeps the one-click seeded demo flow (`DemoLoginCard`) unchanged; the header link toggles between "Open demo" and "Sign in to an account".
- Header sign-out (`workspace-navigation.tsx`) calls the existing CSRF-protected `POST /auth/logout`, shows "Signing out…" pending state, returns to sign-in, and shows a retryable alert if logout does not complete.
- Signup/workspace-creation flows keep routing to `/login`; a returning user can now reach their own workspace instead of only the demo.
- The old marketing slogan/three-promise composition on auth pages was replaced with concise task instructions in `app/login/layout.tsx` and `auth.css`.
